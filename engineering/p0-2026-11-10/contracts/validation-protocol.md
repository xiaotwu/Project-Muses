### Opus seek 结果的精确含义

已有一次 1.5 秒 seek 测试中，48 kHz 的完整参考解码有 192,000 帧；seek 输出有 120,024 帧，报告的首帧 PTS 为 1.5000000。测试在请求位置的 **±48 帧搜索窗口**内，与同一构建的完整解码对齐，最小 RMS 差异出现在参考索引偏移 **−24 帧**，即返回波形相对名义请求位置早约 **0.5 ms**；对齐后 RMS 差异为 `0.0000546`。[原始结果](../audio/evidence/final-run/local.jsonl)

该 WebM 的时间基为 `1/1000`，因此容器时间戳的离散精度是相关因素；但本次实验没有独立分离时间戳量化、解码器 preroll／skip 处理及寻址行为的贡献。不能声称偏差必然完全由量化造成，不能把 ±48 帧的测试搜索窗口当成已证明的全局误差上限，也不能声称所有 Opus seek 都固定偏移 0.5 ms。该参考解码使用相同 FFmpeg 构建，亦不是独立外部真值。正式验收须增加非周期性已知样本素材、多个 seek 点及不同容器／编码延迟组合，分别报告原始时间戳、实际样本偏差和允许误差。

## 3. 在线来源身份语料的冻结要求

首声比较组至少包含 **30 个不同的、预先验证可播放的来源限定 ID**，另建不可用／受限等负例组；因此完整身份语料的总数应超过 30。不同编码格式、重复播放同一曲以及同一曲的队列实例不能充当新的来源身份。测试类别可以重叠，但必须有明确覆盖表。

| 覆盖项 | 冻结前的最低要求 |
| --- | --- |
| 同名异录音 | 至少三个同名组、每组至少两个不同来源 ID；标注艺人、录音／发行信息及“不应自动替换”的关系 |
| 版本差异 | 至少两个版本族、每族至少三个来源 ID；合计覆盖 studio/live、原版/remix、radio edit 或 clean/explicit 等编辑差异，并标注时间轴是否等价 |
| 多语与字符 | 至少三个中文、三个日文、三个拉丁文字条目；包含中英日混排、标点／空格／Unicode 差异及至少一组同名或音译冲突。标题翻译不能制造新的曲目 ID |
| MV／音频 | 至少两组可比较但有独立来源身份的 MV 与音频版本；有额外片头、章节或不同演出时禁止直接复用进度／歌词时间轴 |
| 媒体特征 | 实际可选的 AAC/M4A 与 Opus/WebM、不同采样率、短内容与长内容；至少一个长播客／章节样本。不存在的来源能力不能靠修改扩展名补足 |
| 负例 | 明确选择不存在／移除、私有或需授权、当前地区或账号受限、失效缓存／过期解析等病例；各有预期错误与可恢复行为。不得越过授权或地区限制来造“成功” |
| 队列上下文 | 相同来源 ID 在集合与 Up Next 中的多个实例，列表中间起播，上一首／下一首和不可用条目跳过；实例单独标记，但不增加来源身份计数 |

每个病例冻结：稳定 `case_id`、来源及稳定 ID、期望录音／版本、来源页面、艺人和时长证据、媒体种类、可用账号／地区条件、预期成功或失败、来源允许的能力、音频起点特征及验证时间。未知录音关系标为未知，不能用同名和近似时长代替人工标注。可播放组还须有来源身份与实际所听内容一致的确认；部分 HTTP 响应或已解析 URL 不能完成此确认。

首声性能组需单列自然静音片头长度。优先冻结起始非静音位置已知且不超过 250 ms 的主组，以减少内容片头对启动能力的混淆；带明显静音片头的真实内容作为独立组保留。两组均报告实际“点击到听见内容”的原始时长；如另报减去已知片头后的启动延迟，必须并列原值、片头测量方法及误差，不能只展示修正后的较小数字。

记录应保存稳定身份而非长期保存签名媒体 URL。账号使用测试别名，不写入 token、cookie、授权头或浏览器资料。已允许保存的完整媒体才能记录文件哈希；否则明确使用何种允许保留的元数据／短证据与内容一致性方法。当前没有已完成的 30 项清单，不能用本节要求自动生成“已验证”状态。

## 4. 冷、热、缓存、账号和网络必须分开标记

“冷启动”不是一个足以复现的标签。每次尝试保存以下独立维度，禁止将不同条件混算后宣称统一 p95。

| 维度 | 必须记录的状态 |
| --- | --- |
| 进程 | 新进程且没有前一次自有播放／解析工作；已运行但该曲未播放；同会话重播。启动应用耗时与点击后耗时分别记录 |
| 解析／连接 | 未命中解析结果与预取；有效解析结果命中；过期结果；是否已有可复用连接。连接未被证实关闭时写未知，不声称绝对网络冷态 |
| 媒体 | 无媒体字节；部分缓存；完整可重建缓存；用户明确离线下载。缓存命中必须有实际命中证据 |
| 元数据与系统缓存 | 元数据／封面状态、文件系统页缓存和 DNS/TLS 等可观测状态。系统缓存无法控制时保留为已知限制，不清理共享 OS 缓存来伪造干净环境 |
| 账号 | 无登录的公开会话；已明确授权且有效的账号别名；过期／撤销；切换中。不能在授权失败后静默降级到公开会话并计作原请求成功 |
| 网络 | 固定参考网络、受控限速／延迟／丢包、断网及恢复；记录配置、实际观测、成本策略、网络变化时间与来源响应。蓝牙／AirPlay 是输出路由，不是网络质量标签 |
| 输出与前台状态 | 设备／路由别名、采样率、应用音量与静音状态；前台、后台、已锁屏；设备更改、中断与恢复事件 |

主冷点播比较采用：新进程、无该曲解析／媒体命中、无预解码下一曲、固定账号条件和参考网络。仅重置隔离测试目录中经核验可重建的自有状态；用户库、明确离线下载、原账号真值及共享依赖不能被删除。系统页缓存等无法清空的条件如实记录。“热解析但无媒体”“完整缓存”“明确离线”“账号过期”“弱网”各开独立组。主组与基线不具备等价隔离条件时，先报告限制并解决可比性，不能强行汇总。

## 5. 首次真实出声的测量点

主指标定义为 `L_sound = t_sound − t_action`，使用同一个校准后的单调时间轴。

| 时间戳 | 定义与用途 |
| --- | --- |
| `t_action` | 操作系统派发本次 click/tap/媒体键播放激活事件的时间；在冻结清单中选定具体事件点与采集方法，两版保持一致。另可记录应用收到／接受请求时间，用于拆分 UI 延迟 |
| `t_resolved`、`t_first_byte` | 解析完成、网络首字节；只诊断来源链路，不能作为首声 |
| `t_pcm_ready` | 解码器产生该请求的首个有效 PCM；不能证明已送到设备 |
| `t_output_submitted` | 正确播放 generation 的首个非零样本送入原生输出回调；只给出提交端时刻，不能证明 DAC、扬声器或人耳已听见 |
| `t_sound` | 选定真实输出链路的采集端首次检测到、并确认属于目标内容的声音。冻结输出端回采／声学采集方法、音量、采样率、时钟映射和检测器参数 |

采用可校准的实际输出端回采或声学记录；对数字环回必须注明采集点，位于硬件呈现之前的环回只能提供中间指标。人耳确认是另一条证据，不能用监听数字环回来冒充扬声器验证。基线无内部打点时使用同一套外部输入事件／音频采集；若为基线增加测量补丁，记录补丁与构建哈希，并标成“经测量补丁构建的 0.6.3”，不能冒称原发布字节。

冻结前先用自有已知起点素材校准：记录输入事件标记与采集时钟的偏移／漂移、音频输入和输出延迟、视频帧率（若使用录像定位操作）、检测精度与误差界限。音频 onset 检测使用冻结的噪声底／幅度阈值和连续窗口，并以预先标注的片头／波形确认目标内容，排除提示音、按键声、上一首余音及广告。阈值不在看到快慢结果后调整。没有可信同步或采集失败时，记录 `measurement_invalid`，不能填入估算首声。

每条记录保留原始操作时间、原始 onset、校准参数／版本、误差范围和短证据引用；如展示校准值，同时保留未修正值。连续记录只保留必要的有界事件窗口及摘要，不默认保存完整长时间录音。纯静音输出、回调次数、非零 PCM、进度条、首字节和人工按秒表均不能单独通过毫秒级首声门槛。

## 6. 至少 100 次尝试及统计规则

主冷点播组在**基线与每个候选构建各至少 100 次**，覆盖同一至少 30 个已冻结可用来源 ID。每个身份至少三次，其余次数按事前固定的平衡安排分配；先固定随机种子、尝试顺序和 A/B 交错方式，再启动比较。不得把两版、不同账号、冷热态或不同网络的次数相加凑够 100。

0.6.3 对照在这里专指 macOS 同机比较。iOS 与 Windows 的自身基线（如有）及候选版本分别建立组；缺少可比旧版时只报告候选实测，不借用 Mac 的改善幅度或完成状态。

每个计划项只有一个初始用户动作。应用内部的解析重试／格式回退属于该项，计时从原 `t_action` 连续计算；重新点播放产生新尝试并保留原失败。记录初始来源、最终来源与版本关系，错曲／未经允许替换即失败，不能因“有声音”算成功。预先冻结观察超时，默认 30 秒；该值用于停止观察，不改变 p95 ≤5 秒的目标。

结果至少包含：计划数、实际开始数、有效测量数、无效测量数、正确可听成功数、播放器错误、来源拒绝／变更、网络失败、超时、错曲、取消／人工干预、各重试次数。来源或网络原因必须单列，但已开始的主组尝试不得据此从总成功率分母静默删除。冻结后来源变成不可用时保留失败和变化证据；需要重新配对时建立新语料版本，旧组结果继续可见。

仅采集设备失效／时间轴无法同步等测量问题可标无效；慢、失败、来源拒绝或途中网络变化都不是“测量无效”。事先规定无效项的补测规则，例如按同一条件在固定追加位置补一次，同时保留原记录。无效项未完成解释和补足前，组结果为不完整，不能宣称达到门槛。专门的取消／故障注入病例使用独立预期结果，不混入正常首声主组。

报告全部尝试的成功率及 p50/p95，并给出样本数、失败数、置信区间或其解释。分位数算法预先固定为排序后 nearest-rank（`ceil(p×N)`）；对没有出声的有效尝试，保留超时／右删失标记，计算操作成功视角的分位数时置为无穷，不能填成零或删除。可另列“仅成功项延迟”，但必须明确其条件性，并与全尝试结果并排。100 次观测的 99% 成功率不等于总体可靠性已被证明为 99%。

当前参考目标维持：主冷点播 p50 ≤2.5 秒、p95 ≤5 秒、观测成功率 ≥99%；已准备下一首的手动切换 p95 ≤750 ms 单列。任何合理化调整须先保留原失败证据、说明原因并增加协议版本，不回写旧阈值。未经同样样本量和条件验证的热态／弱网分组只作描述性结果，不借用主组结论。

## 7. 原生可听与四小时运行是独立验收

各平台使用真实原生应用和真实设备确认所听内容、单一主声音输出、暂停、seek、上一首／下一首及交接。记录观察者确认、时间、病例、路由、应用音量／静音状态和异常；未有人确认的项目标为“可听性未观察”。至少逐一确认主组的各来源身份，并覆盖每种宣称支持的路由和关键交接；仪器定位负责时间，人的观察负责实际可听性与明显音质问题。

iOS 的前台播放、退到后台、物理锁屏、锁屏后才解析并装载下一曲、路由改变及系统中断分别留证。为下一首提前解码不能代替“锁屏后获取下一首”；不因静音维持回调而宣称完整后台音乐体验。Mac 原生成功不能替代 iOS 真机结果，iOS 模拟器或交叉编译也不能代替设备结果。

每个发行候选的**至少两次、各四小时持续播放**在后续独立运行，不由 100 次短点播或当前 P0 回调推导。记录累计真实播放时长、总墙钟时长、暂停和中断时长；每次应达到四小时有效播放，并覆盖网络波动、路由变化、暂停恢复和人工插队。验收为零播放器造成的崩溃、队列错位、重复推进和不可恢复中断，真实声音与进度同时核验。

四小时测试前另行冻结事件脚本、故障时刻、输入序列、观测方案及磁盘／内存预算。长录音可能产生 GB 级数据，须先量真实可用空间、设总量与停止阈值；优先保留有界异常前后音频窗口、时间摘要、RSS／缓存高水位及失败回执。测试后核对进程与打开文件，再将已失效的自有 scratch 按项目规则移入专用 Trash；不将编译缓存或整场原始录音默认作为证据档案。当前没有四小时成绩。

在第一条计分尝试前，由执行负责人一次性核对并哈希以下文件；这是一道实际准备门槛，本协议本身没有生成这些尚不存在的完成清单。

1. **构建清单**：基线 0.6.3 的实际发布来源、tag/commit、包与可执行文件 SHA-256、签名／架构／安装限制；候选版及依赖的同类信息；所有测量补丁、启动参数和功能开关。
2. **环境清单**：硬件、OS 版本／build、SDK／编译器、原生输出与采集链路、音量、采样率、账号别名、网络配置／测量、隔离目录和各缓存状态。明确无法控制的项。
3. **语料清单**：至少 30 个可用来源身份与额外负例、版本关系、验证时刻、内容起点、来源能力、允许保留的媒体／证据哈希及预期结果；逐行审核后才能标为 frozen。
4. **执行清单**：每版至少 100 条计划项、固定随机种子及顺序、冷热／网络／账号分组、超时、重试归属、无效测量补测规则、暂停条件、统计公式与阈值。
5. **测量与安全清单**：工具／检测器版本和哈希、时钟校准回执、噪声阈值、原始证据窗口、磁盘停止阈值、脱敏字段与自有 scratch 清理边界。维护脚本和计划执行前复核哈希。

将上述哈希、协议版本、负责人、冻结时间和 `status=frozen` 写入统一 campaign manifest；任一缺项时状态保持 `draft/incomplete`，不得发起声称可比的正式统计。每条回执关联该 manifest 哈希及唯一 attempt ID。冻结后变更源身份、二进制、系统、路由、网络类别、缓存口径、检测阈值或统计规则时，新建版本／分组，不修改原记录，不只重跑失败项来替换结果。

完成后交付原始计数、完整尝试表、条件分组、失败原因、首声分位数与误差、原生可听记录、样本覆盖及未完成项。Mac 0.6.3 与新版本的同机差异只有在这套冻结和测量完成后才能报告；当前的正确表述是“比较方法已定义，基线与正式样本尚未测量”。
